# 1주차 미션 논의 — compact 전 맥락 스냅샷 (2026-07-04)

> 세션 브랜치명: "1주차 미션". 형제 브랜치 "2주차 미션"·"3주차 미션"·"4주차 미션"이 같은 저장소를 동시에 편집 중이므로,
> 티켓 상태가 이 문서 작성 시점과 다를 수 있다 — 최신 상태는 항상 `ticket/README.md`를 확인한다.

## 이 세션에서 있었던 일 (순서대로)

1. `missions/week-1.md`를 `g23-welcome` / `g23-thinking-partner` / `g23-case-writer` / 공식 커리큘럼 스냅샷과 교차 확인 — 정합 확인됨(수정 없음).
2. "스터디장 사례글" 예시가 "아침 루틴" 하나로 고정된 문제 제기 → **"하루 세 시점"(아침 출근 후 / 점심 식사 후 / 퇴근하기 전)** 원칙으로 대체하기로 결정. 이유: 참가자가 PRO 요금제 + 직군이 다양해 특정 업무 하나로 고정하면 공감 못 하는 사람이 생김. 이 세 시점은 직군과 무관해 "생각을 적게 해도" 후보를 고르기 쉽다.
   - 반영: `g23-welcome` ⑤ 미니 실습 기본값 안내(“마땅한 게 없으면 …” 문구), `week-1.md`의 "스터디장 사례글" 줄.
   - welcome 쪽 디테일(질문 순서·톤, 예시 다양화, 다른 skill로 확산 여부)은 [[021-welcome-daily-moments-detail]]로 분리 — 아직 추가 논의 전.
   - 같은 원칙을 "2주차 미션" 세션이 `week-2.md` **전체 구조**에 이미 훨씬 본격적으로 반영함 — 목표 자체가 "하루 한 순간을 10분 안에 자동화하기"로 바뀌어 있음(확인 완료, 2026-07-04 시점).
3. **핵심 미해결 논쟁: k-skill을 1주차부터 쓸지, 2주차로 미룰지.**
   - 공식 커리큘럼 원문 근거: 1주차 과제 = "**템플릿**과 함께 첫 번째 스킬", 2주차 과제 = "**k-skill을 활용**해 두 번째 스킬" → 문구상 2주차 쪽에 무게가 실림.
   - 반박 근거: 루트 `CLAUDE.md`가 스터디 전체를 "0부터 발명하지 않는다 — k-skill을 **출발점**으로 삼는다"로 정의하고 있어, 1주차부터 있는 게 자연스럽다는 반론도 있음.
   - **실제 충돌 발견**: `week-2.md`(다른 세션이 이미 `done` 처리한 [[017-week2-curriculum-alignment]])의 순서 3번이 "**1주차 흐름을 반복한다**: 참고 사례 찾기 → skill-creator로 SKILL.md 만들기 → 써보기"로 되어 있음 — 즉 **1주차가 이미 k-skill 참고 단계를 포함한다고 전제**하고 쓰여 있다. 1주차에서 k-skill을 완전히 빼면 이 문구가 근거를 잃는다. → 이건 "2주차 미션" 세션과 조율이 필요한 지점.
   - **여기서 결론이 나지 않았다.** 논의는 "그럼 1주차에 넣는다면 어떻게 넣을지" 쪽으로 자연스럽게 넘어감.
4. 1주차에 k-skill을 넣는다면 실무적 문제 제기: k-skill 사례들은 환경(API 키·로그인·브라우저 자동화 도구)에 따라 참가자별로 실행 가능 여부가 갈린다. 1주차는 참가자 전원이 "와우 포인트"를 느껴야 하는 첫 순간이라, 이 격차가 특히 치명적.
   - 티켓 [[023-week1-kskill-environment-independent-wow]] 생성.
   - 초안 분류(아직 확정 아님, 사용자 확인 대기 중):
     - **Tier A** — 텍스트 입력→출력만 필요, API 키·로그인·설치 불필요 (예: AI 윤문, 요약, 이메일 초안)
     - **Tier B** — 로컬 파일·기본 CLI 정도 필요
     - **Tier C** — 외부 서비스 API·로그인·브라우저 자동화 필요
   - 공식 결과물 예시 3개를 이 기준에 대입: **AI 윤문 = Tier A**, **사업자등록·등기부등본 자동화 = Tier C**, **쿠팡·네이버 장보기 = Tier B~C 경계**(브라우저 자동화 도구 유무에 따라 갈림).
   - AI 윤문이 1주차 후보 1순위로 보인다는 잠정 제안까지 하고, 사용자에게 "이 분류 기준이 맞는 방향인지" 확인을 요청한 상태 — **다음 세션은 여기서부터 이어가면 된다.**
