# g23-missions — 주차별 미션 안내

참가자가 4주 산출물 기준을 잃지 않게 한다. 미션 원문은 `reference/week-1.md` ~ `reference/week-4.md`에 있다.

> `reference/`의 다른 파일(`official-curriculum.md`)과 성격이 다르다 — `week-N.md`는 이 스킬이 켜질 때마다
> **매번** 읽는 본체 콘텐츠이고, `official-curriculum.md`는 문구 근거 확인이 필요할 때만 여는 온디맨드 백업이다.

## 진행 방법

1. 지금 몇 주차인지 확인한다. 모르면 참가자에게 묻는다. ("지금 몇 주차인가요? 아니면 처음이면 1주차부터 시작해요.")
   - 참가자가 “2주차 미션 알려줘”처럼 주차를 말했다면 다시 묻지 않는다.
   - `gpters-k-skill-report-{닉네임}.html`(4주 로드맵)과 OT 사례 초안이 아직 없으면
     첫날 OT를 마치지 않은 것이다. 셋업이 안 됐으면 **"스터디 시작 도와줘"**(→ `g23-setup`),
     로드맵·OT가 남았으면 **"내 업무로 4주 로드맵 만들자"**(→ `g23-welcome`)로 안내한다.
   - 로드맵 HTML과 OT 초안이 손에 있으면 첫날 OT를 마친 상태다. 같은 OT 과정을
     반복시키지 않고 2주차로 연결한다. (내 업무 첫 skill은 1주차 안에 만든다 — `week-1.md` 참고.)
2. 해당 주차 파일(`reference/week-N.md`) **하나만** 읽는다. 전체 미션 파일을 통째로 읽지 않는다. (토큰 절약)
3. 그 주차의 **목표 / 함께 하는 것 / 손에 남는 것 / 멤버 과제**를 짧게 정리해 안내한다.
4. 참가자가 원하면 체크리스트로 진행 상황을 하나씩 점검한다.

## 4주 전체 흐름 (한눈에)

| 주차 | 핵심 | 손에 남는 것 |
|---|---|---|
| 1주차 | k-skill 체험 후 내 업무 첫 skill 만들기 | 첫 skill + 4주 로드맵 + OT 초안 |
| 2주차 | 10분 안에 처리하는 두 번째 skill | 두 번째 skill |
| 3주차 | 만든 skill들을 순서대로 실행하는 skill로 묶기 | 통합 skill 1개 |
| 4주차 | 4주 사용 경험 공유 + 사례글 | skill 3개 + 사례글 1개 |

> 사례글은 4주차만의 일이 아니다. 첫날에는 OT 초안을 만들고, 이후 실제 사용 경험이
> 쌓이면 주차별 사례로 발전시킨다. 정확한 요구는 해당 주차 파일로 확인한다.

## 최종 결과물 (4주 끝에 반드시)

1. 자기 업무에 실제로 쓰는 skill **3개**
2. 4주 사용 경험 기반 **사례글 1개**
3. 각 skill의 짧은 **사용 기록** (목적 / 사용 전·후 / 막힌 점 / 고친 점)

## 연결

- skill 후보를 못 고르겠다면 → `g23-thinking-partner` (막히면 비슷한 k-skill 사례를 자동으로 찾아준다)
- 사용 기록·사례글을 쓸 때 → `g23-case-writer` (양식도 그 skill이 안내한다)

> 원본 커리큘럼 근거: `reference/official-curriculum.md` (gpters.org 공식 스터디 페이지 스냅샷). 주차 내용을 고치거나 문구 근거를 확인할 때만 참고한다 — 평소 안내에는 읽지 않는다.
