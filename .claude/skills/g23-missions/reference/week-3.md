# 3주차 — 만들어둔 skill들을 함께 쓰기

> 목표: 여러 skill을 **하나의 업무 흐름**으로 통합해 한 번에 처리해본다.

skill 하나를 실행하면 등록해둔 여러 skill이 순서대로 이어서 도는 걸 만드는 게 이번 주 핵심입니다.

## 함께 하는 것
- 1, 2주차에 만든 skill 점검
- 여러 skill을 한 번에 실행하는 흐름 설계
- 반복 사용을 막는 불편함 제거하기

## 이번 주 순서
1. 지금까지 만든 skill(1, 2주차)을 점검한다: 계속 쓰는 것 / 안 쓰는 것 구분. 안 쓰게 된 게 있다면 왜인지 보고, **다시 켜고 싶어지는 형태**로 다듬거나 과감히 접는다.
2. `g23-thinking-partner`로 "지금 있는 skill들을 어떻게 하나로 묶으면 좋을지" 되물어본다. (예: "아침엔 A, 점심엔 B를 따로 쓰고 있다면 — 하나로 이어붙일 만한가요?")
3. 묶을 조합이 마땅치 않다면, 같은 대화에서 방향을 바꿔 **세 번째 skill을 새로 만드는 쪽**으로 넘어간다.
4. 묶기로 했다면 `skill-creator`로 여러 skill이 순서대로 이어서 도는 하나의 skill을 만든다. 이름은 자유롭게 정한다. 새로 만들기로 했다면 그 skill 자체를 `skill-creator`로 만든다.
5. 사용 기록을 갱신한다.
6. `g23-case-writer`로 이번 주 경험(다양한 업무를 한 번에 처리한 사례)을 사례 게시글로 정리하고, gpters.org에 스터디 태그(예: `23기 K스킬자동화`)로 발행한다.

## 손에 남는 것
- [ ] 여러 skill이 순서대로 이어서 도는 skill 1개 (또는 고도화된 기존 skill)
- [ ] gpters.org에 발행한 사례 게시글 1개 (스터디 태그, 예: `23기 K스킬자동화`)
- [ ] (권장) 여기까지 skill **3개**가 모이면 최종 결과물 요건에 가까워집니다

## 멤버 과제
만들어둔 skill들을 **하나의 흐름으로 묶어 실행한 경험**을 담은 사례 게시글을 gpters.org에 스터디 태그(예: `23기 K스킬자동화`)로 발행합니다.

## 이번 주 포인트
- 새 걸 더 만드는 것보다, **실제로 계속 쓰게 만드는 것**이 목표입니다.
- "다시 켜고 싶어지는 이유"가 무엇인지 한 줄로 적어보세요.
