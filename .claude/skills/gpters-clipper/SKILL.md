# gpters-clipper — 지피터스 게시글 정확하게 클리핑하기

## 왜 이 스킬이 필요한가

[[024-clip-verbatim-excerpts]]에서 발견된 문제: 기존 클립 50개(014)는 전부 AI가 자기 말로 다시 쓴 요약뿐이라, "사람이 실제로 쓴 문체"를 보여줘야 하는 문체 레퍼런스 목적에 맞지 않았다. AI 문체를 AI 문체로 대체한 셈. 이 스킬은 그 실수를 구조적으로 막는다: **원문 발췌 없이는 클립을 완성 처리하지 않는다.**

## 입력

- 게시글 URL 1개(또는 여러 개) — 참가자가 고른 것.
- URL이 없으면 먼저 `gpters-case-researcher` 에이전트로 후보 3~5개를 찾아 참가자가 고르게 한다.

## 절차

1. **본문을 연다.** 게시글 URL을 WebFetch로 직접 연다 (원본 URL 그대로 — 원문 전체 요청).
   - 여러 건을 한 번에 처리할 땐 **동시 호출 대신 순차로** 연다. 동시 다건 요청 시 간헐 502가 날 수 있다([[015-clip-blank-body-diagnosis]]에서 재현됨).
   - 비거나 에러(502 등)가 나면 같은 URL을 최대 2회 재시도한다.
   - 그래도 안 열리면 **클립을 만들지 않는다.** 제목만으로 요약을 지어내는 것이 가장 나쁜 결과다. 실패 목록에 URL과 사유(`로그인 필요` / `일시 실패(재시도 2회)`)를 남긴다.
2. **핵심을 뽑는다.**
   - 왜 클립했나 (한 줄)
   - 핵심 요약 (2~3줄, 내 말로 재구성 OK)
   - 내 업무에 어떻게 쓸까 (1~2줄)
3. **원문 발췌를 뽑는다 — 이 스킬의 핵심.**
   - 원문에서 실제로 쓰인 문장 2~3개를 **글자 그대로** 복사한다. 따옴표로 감싼다.
   - 문체·어조·표현이 살아있는 문장을 고른다 (도입부 훅, 구어체 표현, 구체적 수치가 담긴 문장 등) — `_style-reference.md`가 참고할 실제 재료가 된다.
   - **AI가 재구성한 문장은 여기 넣지 않는다.** 이 섹션이 요약처럼 읽히면 실패다.
   - `## 글쓰기에서 훔칠 점`(문체 관찰, 1~3줄)도 남긴다.
4. **저장한다.**
   - `ticket/clips/_template.md`를 복사해 `ticket/clips/NNN-짧은-슬러그.md`로 저장 (NNN = 다음 연번).
   - 기존 클립과 URL 중복이면 만들지 않는다.
5. **인덱스를 갱신한다.**
   - `ticket/clips/README.md` "모은 클립" 목록에 한 줄 추가.

## 산출물 형식

`ticket/clips/_template.md` 그대로 따른다 (frontmatter: title/source/category/clipped/tags + 왜 클립했나 + 핵심 요약 + `## 원문 발췌` + 내 업무에 어떻게 쓸까 + 글쓰기에서 훔칠 점).

## 하지 않는 것

- 본문을 못 열었는데 제목/URL 슬러그만으로 요약을 지어내지 않는다.
- 원문 발췌를 패러프레이즈하지 않는다.
- 이미지·첨부파일을 다운로드하지 않는다.
- 로그인 벽을 우회하려 하지 않는다 (표시만 남긴다 — 브라우저 자동화 폴백은 참가자 판단).

## 관련

- `.claude/agents/gpters-case-researcher.md` — 후보 조사 전담 (넓게 훑어 후보만 물어옴). 이 스킬은 그다음 단계, "고른 글을 정확히 클립하는" 역할.
- [[024-clip-verbatim-excerpts]] — 이 스킬이 생긴 배경(50개 클립 결함 진단·수정).
- [[015-clip-blank-body-diagnosis]] — 동시 요청 시 간헐 502 진단(순차·재시도 규칙의 근거).
