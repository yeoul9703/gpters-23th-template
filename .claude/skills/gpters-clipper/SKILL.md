# gpters-clipper — 지피터스 게시글 정확하게 클리핑하기

## 원칙 한 줄

클립의 가치는 **사람이 실제로 쓴 문체가 그대로 보존되는 것**이다. AI가 요약·재구성한 문장은 문체 레퍼런스로 무의미하다. 그래서 본문 수집은 전부 `scripts/`의 스크립트가 하고, 모델은 그 출력을 **붙여넣기만** 한다 — 다시 타이핑하는 순간 verbatim이 깨진다. (프롬프트 지시만으로는 이 원칙이 지켜지지 않을 위험이 있어 스크립트로 강제한다.)

## 입력

- **게시글 URL** — A·B를 건너뛰고 1단계부터.
- **주제/태그만** ("자동화 후기 사례 찾아줘") — A·B로 후보를 먼저 찾고, 확정된 URL마다 1단계부터.

## 절차

A. **(주제/태그만 왔을 때) 후보를 찾는다 — 키워드 검색을 우선한다.**
   - 태그 기반 목록은 딱 맞는 태그가 있을 때만 잘 먹는다. 태그 없는 주제는 후보를
     하나도 못 찾는 걸 실측(AB 테스트)으로 확인했다. 그래서 **핵심 키워드를
     5~10개로 넓혀 `WebSearch("site:gpters.org <키워드>")`로 먼저 찾는다**
     (`gpters-case-researcher`와 같은 전략, 이쪽은 더 철저하게 — 후보가 부족하면
     키워드를 더 늘려 계속 찾는다).
   - 그래도 부족하거나 태그가 명확히 있으면 목록도 같이 본다:
     ```
     uv run .claude/skills/gpters-clipper/scripts/fetch_list.py "<목록 또는 태그 URL>"
     ```
     출력은 `제목<TAB>URL` 한 줄씩. 태그 URL: `https://www.gpters.org/ai-study-post?tag_id=<id>`, 전체 목록: `https://www.gpters.org/ai-study-post`. 무한스크롤 첫 배치(~30개)만 잡힌다 — 더 있을 수 있다고 안내하고, 그 이상은 긁지 않는다. `FETCH_FAILED`(exit 1)면 후보를 지어내지 않는다.
   - 키워드 검색·목록 결과를 합쳐 주제와 맞는 후보 3~5개를 추린다.

B. **(주제/태그만 왔을 때) 후보를 사람에게 확인받는다.**
   - 후보 3~5개(제목·URL·왜 맞는지 한 줄)를 나열하고 참가자가 고르게 한다.
   - 확인 없이 대량 클립하지 않는다 — 1건씩 확인 후 클립.

1. **본문을 가져온다.**
   ```
   uv run .claude/skills/gpters-clipper/scripts/fetch_post.py "<게시글 URL>"
   ```
   - stdout이 이후 모든 단계(요약·발췌·전문)의 **유일한 소스**다.
   - `FETCH_FAILED`(exit 1)면 **클립을 만들지 않는다** — 제목만으로 지어내는 것이 최악의 결과다. 실패 목록에 URL과 stderr 메시지를 그대로 남긴다.
   - 여러 건은 한 번에 하나씩 **순차로** 실행한다 (동시 실행 금지 — 동시에 여러 건 요청하면 서버가 간헐적으로 502를 내는 걸 확인했다).
   - WebFetch 도구는 쓰지 않는다 — 모델이 요약·재구성해 verbatim이 깨진다.

2. **핵심을 뽑는다.** 왜 클립했나(한 줄) / 핵심 요약(2~3줄, 내 말 OK) / 내 업무에 어떻게 쓸까(1~2줄). 1단계 stdout에 작성자 이름(바이라인)이 보이면 `author`에 적는다 — 안 보이면 지어내지 말고 빈 값으로 둔다.

3. **원문 발췌를 뽑는다.** 1단계 stdout에서 문체가 살아있는 문장 2~3개를 **글자 그대로** 복사해 따옴표로 감싼다. `## 글쓰기에서 훔칠 점`(문체 관찰 1~3줄)도 남긴다. AI가 재구성한 문장이 섞이면 실패다.

4. **원문 전문을 담는다 — 이 스킬의 핵심.** 1단계 stdout **전체**를 `## 원문 전문` 섹션에 **4-backtick 펜스(````)**로 감싸 그대로 붙여넣는다. 본문 안에 ``` 코드블록이 있어도 4-backtick 덕에 구조가 안 깨진다. 요약·재구성·재배열·생략 금지 — "붙여넣기"이지 "옮겨적기"가 아니다. 출력 끝부분에 그 글의 **댓글 텍스트가 이어져 있을 수 있다**(스크립트 설계상 허용된 여분 — 아래 scripts/ 참고). 눈에 띄면 끝의 댓글 부분만 잘라내고 붙여넣어도 된다. 애매하면 그대로 둔다 — 본문을 실수로 자르는 것보다 낫다.

5. **저장한다.** `data/gpters/_template.md`를 복사해 `data/gpters/NNN-짧은-슬러그.md`(다음 연번). URL이 기존 클립과 중복이면 만들지 않는다.

6. **인덱스를 갱신한다.** `data/gpters/README.md` "모은 클립"에 한 줄 추가.

## scripts/ — 뭘 해주나

둘 다 Python이고 `uv run <경로> "<url>"`로 실행한다(리포 루트 기준). uv가 의존성(requests)을 격리 환경에 자동 설치한다 — venv 세팅 불필요 (`g23-setup/reference/setup-guide.md` §3 uv 컨벤션).

- `fetch_post.py <게시글 URL>` — 본문을 verbatim 마크다운으로 출력. gpters.org는 JS SPA라 Jina Reader를 경유하되, `x-target-selector: article.prose`로 글 콘텐츠만 뽑는다 → 사이트 헤더·네비·추천글·뉴스레터 위젯이 애초에 안 들어온다. 댓글도 같은 요소를 써서 본문 뒤에 이어질 수 있는데, 이건 의도된 트레이드오프다 — 셀렉터를 좁히면 헤딩·이미지가 형제 블록인 글에서 본문이 **소리 없이 유실**되는 걸 실측으로 확인했고, 조용한 유실보다 여분 포함이 낫다. 재시도(backoff)·rate limit(429) 대기·죽은 링크 판정·이미지 라인 제거까지 처리.
  - 알려진 한계: Jina의 렌더 스냅샷이 비결정적이라 드물게 헤딩·링크가 빠진 부분판이 온다(코드로 못 막음 — 스크립트 주석 참고). 출력이 글 분량 대비 의심스럽게 짧으면 시간을 두고 재실행해 더 긴 쪽을 쓴다.
- `fetch_list.py <목록/태그 URL>` — 목록 페이지에서 게시글 `제목<TAB>URL` 열거 (첫 배치만).

## 하지 않는 것

- 본문을 못 열었는데 제목/URL로 내용을 지어내지 않는다.
- 원문 발췌·원문 전문을 패러프레이즈하지 않는다. 스크립트 stdout을 다시 타이핑하지 않는다.
- WebFetch로 본문을 가져오지 않는다.
- 이미지·첨부파일을 다운로드하지 않는다.
- 로그인이 필요해 보이는 글을 우회하지 않는다 (실패로 표시만 — 브라우저 폴백은 참가자 판단).
- 목록 첫 배치 이후를 억지로 긁지 않는다.
- 후보 확인(B) 없이 대량 클립하지 않는다.

## 관련

> `scripts/`를 두는 건 예외적인 구성이다 — 이유는 위 '원칙 한 줄' 참고.

- `.claude/agents/gpters-case-researcher.md` — 가벼운 참고용 검색 담당(키워드 검색
  전략). data에 실제로 저장까지 할 때만 이 스킬(gpters-clipper)로 넘어온다.
