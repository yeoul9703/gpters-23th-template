# gpters-clipper — 지피터스 게시글 정확하게 클리핑하기

## 왜 이 스킬이 필요한가

[[024-clip-verbatim-excerpts]]에서 발견된 문제: 기존 클립 50개(014)는 전부 AI가 자기 말로 다시 쓴 요약뿐이라, "사람이 실제로 쓴 문체"를 보여줘야 하는 문체 레퍼런스 목적에 맞지 않았다. AI 문체를 AI 문체로 대체한 셈. 024에서 원문 발췌(2줄)를 추가했지만 그것만으론 글 전체의 구성·논증 흐름은 안 보였다 → [[026-clip-full-body-text]]에서 원문 전문을 추가로 요구하게 됨. 이 스킬은 그 실수들을 구조적으로 막는다: **원문 발췌·원문 전문 없이는 클립을 완성 처리하지 않는다.**

## 입력

- 게시글 URL 1개(또는 여러 개) — 참가자가 고른 것. 이 경우 아래 A·B는 건너뛰고 1단계부터 시작한다.
- 또는 주제/태그만("자동화 후기 관련 사례 찾아줘"). 이 경우 아래 A·B로 후보를 먼저 찾은 뒤, 확정된 URL마다 1단계부터 반복한다.

## 절차

A. **(주제/태그만 왔을 때만) 목록으로 후보를 찾는다.**
   - 목록·태그 페이지도 `curl -sL "https://r.jina.ai/<목록 또는 태그 URL>"`로 연다 — WebFetch 도구로 직접 열면 실패한다(2026-07-13 재검증: 다른 섹션 네비 셸만 반환됨). 태그 URL 형식: `https://www.gpters.org/ai-study-post?tag_id=<id>`, 태그 없이 전체면 `https://www.gpters.org/ai-study-post`.
   - 이 fetch는 무한스크롤 첫 배치(~31개)만 잡힌다. 더 있을 수 있다는 안내를 후보 목록과 함께 남긴다 — 그 이상을 긁어오려 하지 않는다(스코프 밖).
   - 받은 마크다운에서 게시글 제목·URL·짧은 요약을 열거해 주제와 맞는 후보 3~5개를 추린다.
B. **(주제/태그만 왔을 때만) 후보를 사람에게 확인받는다.**
   - 후보 3~5개(제목·URL·왜 맞는지 한 줄)를 나열하고, 참가자가 실제로 클립할 것을 고르게 한다.
   - 사람 확인 없이 자동으로 대량 클립하지 않는다 — 이 스킬은 1건씩 확인 후 클립하는 흐름을 유지한다.
   - 확정된 URL마다 아래 1단계부터 반복한다.

1. **본문을 연다 — `curl -sL "https://r.jina.ai/<원본 URL>"` 로, WebFetch 도구는 쓰지 않는다.**
   - WebFetch 도구는 가져온 페이지를 내부적으로 **모델이 요약·재구성**해 돌려준다(도구 설명에 명시됨) — 발췌든 전문이든 verbatim이 아니게 된다. `curl`로 Jina Reader를 직접 치면 페이지의 마크다운 변환 결과를 그대로 받는다(모델 개입 없음). gpters.org는 JS SPA라 원본 URL을 그냥 curl하면 빈 셸만 나온다 — 반드시 `r.jina.ai/` 프리픽스를 거친다.
   - 여러 건을 한 번에 처리할 땐 **동시 호출 대신 순차로** 연다. 동시 다건 요청 시 간헐 502가 날 수 있다([[015-clip-blank-body-diagnosis]]에서 재현됨).
   - 비거나 에러(502 등)가 나면 같은 URL을 최대 2회 재시도한다.
   - 그래도 안 열리면 **클립을 만들지 않는다.** 제목만으로 요약을 지어내는 것이 가장 나쁜 결과다. 실패 목록에 URL과 사유(`로그인 필요` / `일시 실패(재시도 2회)`)를 남긴다.
   - 받은 마크다운에서 맨 앞 메타 헤더 4줄(`Title:` / `URL Source:` / `Published Time:` / `Markdown Content:`)은 제거하고 본문만 남긴다. 이게 이후 모든 단계(요약·발췌·전문)의 유일한 소스다.
2. **핵심을 뽑는다.**
   - 왜 클립했나 (한 줄)
   - 핵심 요약 (2~3줄, 내 말로 재구성 OK)
   - 내 업무에 어떻게 쓸까 (1~2줄)
3. **원문 발췌를 뽑는다.**
   - 1단계 마크다운에서 실제로 쓰인 문장 2~3개를 **글자 그대로** 복사한다. 따옴표로 감싼다.
   - 문체·어조·표현이 살아있는 문장을 고른다 (도입부 훅, 구어체 표현, 구체적 수치가 담긴 문장 등) — `_style-reference.md`가 참고할 실제 재료가 된다.
   - **AI가 재구성한 문장은 여기 넣지 않는다.** 이 섹션이 요약처럼 읽히면 실패다.
   - `## 글쓰기에서 훔칠 점`(문체 관찰, 1~3줄)도 남긴다.
4. **원문 전문을 담는다 — 이 스킬의 핵심.**
   - 1단계 마크다운 **전체**를 `## 원문 전문` 섹션에 코드 펜스(```)로 감싸 붙여넣는다. 본문 안에 `##`, `---` 가 섞여 있어도 펜스 덕에 이 파일의 섹션 구조가 깨지지 않는다.
   - `![Image N...](...)` 이미지 참조 줄만 제거한다(alt 텍스트는 자동 생성 설명이지 저자가 쓴 본문이 아니다). 그 외 본문 문단은 요약·재구성·재배열 금지.
   - 원문 발췌(2~3문장)는 "훅"용 하이라이트, 원문 전문은 글 전체의 구성·논증 흐름을 보여주는 용도 — 둘 다 있어야 완성이다.
5. **저장한다.**
   - `ticket/clips/_template.md`를 복사해 `ticket/clips/NNN-짧은-슬러그.md`로 저장 (NNN = 다음 연번).
   - 기존 클립과 URL 중복이면 만들지 않는다.
6. **인덱스를 갱신한다.**
   - `ticket/clips/README.md` "모은 클립" 목록에 한 줄 추가.

## 산출물 형식

`ticket/clips/_template.md` 그대로 따른다 (frontmatter: title/source/category/clipped/tags + 왜 클립했나 + 핵심 요약 + `## 원문 발췌` + `## 원문 전문` + 내 업무에 어떻게 쓸까 + 글쓰기에서 훔칠 점).

## 하지 않는 것

- 본문을 못 열었는데 제목/URL 슬러그만으로 요약을 지어내지 않는다.
- 원문 발췌·원문 전문을 패러프레이즈하지 않는다.
- **WebFetch 도구로 본문을 가져오지 않는다** — 모델이 요약·재구성해 verbatim이 깨진다. 항상 `curl` + `r.jina.ai`.
- 이미지·첨부파일을 다운로드하지 않는다.
- 로그인 벽을 우회하려 하지 않는다 (표시만 남긴다 — 브라우저 자동화 폴백은 참가자 판단).
- 목록 fetch의 무한스크롤 첫 배치 이후(페이지네이션) 게시물까지 억지로 긁어오지 않는다 — 더 있을 수 있다는 안내만 남긴다.
- 후보 확인(B단계) 없이 목록에서 바로 대량 클립하지 않는다.
