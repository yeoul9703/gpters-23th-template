# g23-setup — 참가자 작업 공간 스캐폴드 + 파악

clone 직후의 템플릿 폴더를 참가자 개인 것으로 만드는 초기화와, 참가자의 업무 맥락 파악을 함께 담당한다.
**참가자의 설정 파일을 자동으로 고치지 않는다.** 무엇을 왜 하는지 설명하고, 특히 되돌리기 어려운 작업(git 재초기화)은 반드시 동의를 받은 뒤에만 실행한다.

## 진행 순서

### 1. 감지
아래 두 가지를 따로 확인한다 — 하나가 끝났다고 다른 하나까지 건너뛰지 않는다.
- **작업 공간 초기화 여부**: `git log`에 참가자 본인 커밋이 있거나 CLAUDE.md에 정체성 블록이 이미 있으면 2번(정체성 기록)·6번(git init)은 건너뛴다.
- **업무 맥락 확보 여부**: CLAUDE.md에 업무 맥락 문단이 이미 있으면 3~4번(업무 파악·개인화)은 건너뛴다.
- 전부 이미 돼 있으면 그 사실만 짧게 알리고 다음 skill(`g23-kskill-intro`)로 넘어가면 된다고 안내한다.

### 2. CLAUDE.md 최소 정체성 기록 (미초기화 시)
채팅으로 딱 두 가지만 짧게 묻는다:
- 성함 (또는 부르길 원하는 이름)
- Claude Code를 이 스터디에서 쓰려는 목적 한 줄 (예: "반복되는 ~업무를 자동화하고 싶다")

받은 답을 루트 `CLAUDE.md` 최상단에 짧은 정체성 블록으로 **바로 작성**한다 (파일 내용을 보여주고 동의를 받은 뒤 쓴다).

### 3. 업무 파악 (skill 후보의 씨앗)
참가자에게 짧게 묻는다:
- 어떤 일을 하나요? (직무/업무 성격)
- 매일·매주 반복되는 작은 작업 3가지는?
- 지금 Claude Code로 해보고 싶은 것 하나는?

답은 4번(개인화)과 `g23-welcome`의 미니 실습에서 쓴다.

### 4. CLAUDE.md 개인화 초안 제안
- 3번 답을 바탕으로 루트 `CLAUDE.md`에 참가자의 업무 맥락을 담을 짧은 문단 초안을 **제안만** 한다.
- 예: "나는 ~한 업무를 하고, 반복 작업은 ~이다. skill은 ~에 초점을 둔다."
- 참가자가 원하면 함께 반영하고, 원치 않으면 그대로 둔다. (2번의 정체성 블록 위에 업무 맥락만 얹는다 — 성함·목적을 다시 묻지 않는다.)

### 5. 시스템 감지 + 설정
- OS를 감지하거나 확인이 안 되면 짧게 묻는다 (macOS / Windows). bash를 전제하지 않는다.
- 참가자의 Claude Code 사용 경험 수준을 가볍게 확인한다 (이후 안내 톤·상세도 조절에 쓴다).
- Windows/Mac 터미널 차이나 Python이 필요해지면 `g23-welcome/reference/setup-guide.md`를 참고해 안내한다 — 내용을 새로 만들지 않는다.
- Claude Code 설정(`.claude/settings.json`, 권한, hooks 등)이 필요하면 직접 고치지 않고 **`/update-config`를 실행하도록 안내**한다.

### 6. git init + 첫 커밋 (미초기화 시)
- 되돌리기 어려운 작업이므로 반드시 순서를 지킨다: **감지 → 제안 → 동의 확인 → 실행.**
- 제안 예시: "기존 clone 히스토리를 지우고 이 폴더를 참가자님 개인 git 저장소로 새로 시작할게요 (`git init` + 첫 커밋). 진행할까요?"
- 동의를 받으면 기존 `.git`을 로컬에서만 재초기화하고 지금까지 만든 파일(CLAUDE.md 정체성·업무 맥락 포함)로 첫 커밋을 만든다.
- **GitHub 원격 저장소 생성은 이 단계에서 하지 않는다** (`gh` 인증이 필요해 실습 시간을 예측하기 어렵다). 원격이 필요하면 참가자가 이후 직접 만들도록 안내만 한다.

## 하지 말 것
- `.claude/settings.json`, hooks, 권한 설정을 자동으로 만들거나 수정하지 않는다 — `/update-config`로 넘긴다.
- 동의 없이 `git init`/히스토리 재작성을 실행하지 않는다.
- GitHub 원격 저장소를 자동으로 만들거나 push하지 않는다.
- 3번(업무 파악) 답을 참가자 대신 해석해 CLAUDE.md에 바로 쓰지 않는다 — 4번은 제안만 하고 동의를 받는다.
- 이미 확보된 정체성·업무 맥락을 다시 묻지 않는다 (1번 감지 결과를 따른다).
