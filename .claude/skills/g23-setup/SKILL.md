# g23-setup — 첫날 작업 공간 준비

clone 직후의 템플릿 폴더를 참가자 개인 것으로 만들고, k-skill을 실제로 설치해 한 번 체험하는 데까지 진행한다.
끝나면 `g23-welcome`으로 넘겨 업무 사례 정리와 4주 로드맵으로 이어간다.
**참가자의 설정 파일을 자동으로 고치지 않는다.** 무엇을 왜 하는지 설명하고, 되돌리기 어려운 작업(git 재초기화)은 반드시 동의를 받은 뒤에만 실행한다.

## 진행 순서 (①→⑥)

이미 끝난 항목은 건너뛰고 필요한 것만 대화형으로 확인한다. 한 번에 한 단계씩 질문은 짧게 한다.

### ① 감지 — 뭘 건너뛸지 먼저 확인

- `git log`에 참가자 본인 커밋이 있거나 `CLAUDE.local.md`에 정체성 블록이 이미 있으면 ②(정체성 기록)·④(git init)는 건너뛴다.
- 전부 이미 돼 있으면 그 사실만 짧게 알리고 ⑤(k-skill 설치·체험)로 바로 간다.

### ② 정체성 기록 (CLAUDE.local.md)

채팅으로 짧게 세 가지를 묻는다:
- 성함 (또는 부르길 원하는 이름)
- 이 스터디에서 Claude Code로 하고 싶은 것 한 줄 (예: "반복되는 ~업무를 자동화하고 싶다")
- 파일에 쓸 영문 닉네임/이니셜 (로마자 형태, 예: kim, park-j, h-lee) — 4주 로드맵 HTML 파일명에 쓰인다

받은 답을 루트 `CLAUDE.local.md`에 짧은 정체성 블록으로 **바로 작성**한다 (파일이 없으면 새로 만든다). 스터디 공용 가이드인 `CLAUDE.md`는 건드리지 않는다 — 개인 이름·목적·닉네임은 `CLAUDE.local.md`에만 쓴다. 새로 만들 때는 파일 맨 위에 한 줄을 남긴다:
```
# 개인 메모 — git에는 안 실립니다(.gitignore)
```
형식 예시:
```
## 정체성

- 성함: 김철수
- 목적: 일일 회의록 자동화
- 파일명 닉네임: kim-cs
```
파일 내용을 보여주고 동의를 받은 뒤 쓴다. (업무 맥락을 더 자세히 담는 개인화는 `g23-welcome`에서 업무 파악과 함께 한다 — 여기서는 정체성 세 줄까지만.)

### ③ 시스템 감지 + 확인

- OS를 감지하거나 확인이 안 되면 짧게 묻는다 (macOS / Windows). bash를 전제하지 않는다.
- 참가자는 Claude Code 기본 사용 경험이 있다고 전제하되, 막히면 필요한 부분만 설명한다.
- k-skill 체험 전에 Node 18 이상과 인터넷 연결을 확인한다. 확인 방법이나 OS별 설치 안내가 필요하면 `reference/setup-guide.md`를 읽는다. 평소에는 읽지 않는다.
- Windows/Mac 터미널 차이나 Python이 필요해지면 같은 가이드를 참고한다.
- Claude Code 설정(`.claude/settings.json`, 권한, hooks 등)이 필요하면 직접 고치지 않고 **`/update-config`를 실행하도록 안내**한다.

### ④ git init + 첫 커밋 (미초기화 시)

- 되돌리기 어려운 작업이므로 반드시 순서를 지킨다: **감지 → 제안 → 동의 확인 → 실행.**
- 제안 예시: "기존 clone 히스토리를 지우고 이 폴더를 참가자님 개인 git 저장소로 새로 시작할게요 (`git init` + 첫 커밋). 진행할까요?"
- 커밋 전에 `.gitignore`에 `/CLAUDE.local.md`가 있는지 확인한다 — 템플릿에 이미 있어야 정상이지만, 없으면 먼저 추가한다. 개인 정보가 git 이력에 남는 걸 막는 안전장치다.
- 동의를 받으면 기존 `.git`을 로컬에서만 재초기화하고 지금까지 만든 파일로 첫 커밋을 만든다. `CLAUDE.local.md`(정체성)는 `.gitignore` 덕에 이 커밋에 자동으로 안 실린다 — 의도된 동작이다.
- **GitHub 원격 저장소 생성은 이 단계에서 하지 않는다** (`gh` 인증이 필요해 실습 시간을 예측하기 어렵다). 원격이 필요하면 참가자가 이후 직접 만들도록 안내만 한다.

### ⑤ k-skill 실제 설치 + 한 번 체험

스터디의 출발점인 k-skill을 손으로 한 번 겪어본다. 여기서 복잡한 결과물을 만들지 않는다 — **"설치가 되고, 한 번 돌아간다"는 경험**만 확인한다.

1. Node 18 이상과 인터넷 연결을 다시 확인한다 (③에서 확인했으면 생략).
2. 아래 두 명령으로 k-skill 플러그인을 설치하게 한다. 첫 번째만 실행하고 끝내지 않는다.
   ```text
   /plugin marketplace add NomaDamas/k-skill
   /plugin install k-skill@k-skill
   ```
   - 첫 명령 뒤 `/k-skill:...`가 안 보이면 두 번째 install 명령 누락부터 확인한다.
   - k-skill 저장소를 별도로 clone하지 않는다.
3. 설치가 됐으면 k-skill 하나를 **실제로 한 번 실행**해본다. 예: `/k-skill:market-kurly-search`로 아무 상품이나 한 번 검색해 결과가 나오는지 눈으로 확인한다.
   - 이건 "k-skill이 어떤 건지" 감을 잡는 체험이다. CSV·표·HTML 같은 산출물을 만들 필요가 없다.
   - Node·인터넷 문제로 안 되면 길게 붙잡지 않는다. 설치까지만 하고, 실행 체험은 리더 안내에 따라 나중에 이어도 된다.

### ⑥ g23-welcome으로 핸드오프

셋업이 끝나면 다음 한 문장을 안내한다:
> 준비 끝났어요. 이제 **"내 업무로 4주 로드맵 만들자"** 라고 말해보세요. `g23-welcome`이 참가자님 업무에 맞는 지피터스 사례를 찾아 4주 자동화 로드맵 HTML까지 이어가고, OT 사례글 초안은 `g23-case-writer`로 넘겨줍니다.

## 하지 말 것

- `.claude/settings.json`, hooks, 권한 설정을 자동으로 만들거나 수정하지 않는다 — `/update-config`로 넘긴다.
- 동의 없이 `git init`/히스토리 재작성을 실행하지 않는다.
- GitHub 원격 저장소를 자동으로 만들거나 push하지 않는다.
- 정체성·업무 맥락을 `CLAUDE.md`(스터디 공용 가이드)에 쓰지 않는다 — 개인 정보는 항상 `CLAUDE.local.md`.
- k-skill 체험 단계(⑤)에서 결과 CSV·HTML·표 같은 산출물 계약을 만들지 않는다. 설치와 1회 실행 확인까지만 한다.
- OS나 요금제를 넘겨짚지 않는다. 모르면 묻는다.
