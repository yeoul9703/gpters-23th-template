# g23-welcome — 첫날 온보딩 도우미

Claude Code를 이미 쓰는 참가자가 50분 안에 **실제 데이터로 첫 skill을 만들고 4주 방향을 보는 경험**까지 진행한다.
①~④ 절차를 이 파일에서 이어가되, ④의 사례글은 `g23-case-writer`, 마지막 주차 안내는 `g23-missions`로 연결한다.
**참가자의 설정 파일을 자동으로 고치지 않는다.** 무엇을 왜 하는지 설명하고, 참가자가 직접 하거나 함께 결정하게 한다. 특히 되돌리기 어려운 작업(git 재초기화)은 반드시 동의를 받은 뒤에만 실행한다.

## 진행 순서 (①→④)

이미 끝난 항목은 건너뛰고, 필요한 것만 대화형으로 확인한다. 한 번에 한 단계씩 질문은 짧게 한다.
시간이 부족하면 장보기 skill의 수정·재실행과 실제 게시글 발행부터 생략한다. 4주 자동화 HTML과 OT 초안은 남긴다.

### ① 작업 공간 셋업 + 참가자 파악

clone 직후의 템플릿 폴더를 참가자 개인 것으로 만드는 초기화와, 참가자의 업무 맥락 파악을 함께 진행한다. 업무 파악 답은 ③의 4주 자동화 로드맵에서 쓴다.

**①-1. 감지** — 아래 두 가지를 따로 확인한다. 하나가 끝났다고 다른 하나까지 건너뛰지 않는다.
- **작업 공간 초기화 여부**: `git log`에 참가자 본인 커밋이 있거나 `CLAUDE.local.md`에 정체성 블록이 이미 있으면 ①-2(정체성 기록)·①-6(git init)은 건너뛴다.
- **업무 맥락 확보 여부**: `CLAUDE.local.md`에 업무 맥락 문단이 이미 있으면 ①-3~①-4(업무 파악·개인화)는 건너뛴다.
- 전부 이미 돼 있으면 그 사실만 짧게 알리고 ②(k-skill 준비)로 바로 넘어간다.

**①-2. CLAUDE.local.md 최소 정체성 기록** (미초기화 시) — 채팅으로 딱 두 가지만 짧게 묻는다:
- 성함 (또는 부르길 원하는 이름)
- Claude Code를 이 스터디에서 쓰려는 목적 한 줄 (예: "반복되는 ~업무를 자동화하고 싶다")

받은 답을 루트 `CLAUDE.local.md`에 짧은 정체성 블록으로 **바로 작성**한다 (파일이 없으면 새로 만든다). 스터디 공용 가이드인 `CLAUDE.md`는 건드리지 않는다 — 개인 이름·목적은 `CLAUDE.local.md`에만 쓴다. 새로 만들 때는 파일 맨 위에 한 줄을 남긴다:
```
# 개인 메모 — git에는 안 실립니다(.gitignore)
```
파일 내용을 보여주고 동의를 받은 뒤 쓴다.

**①-3. 업무 파악** (skill 후보의 씨앗) — 참가자에게 짧게 묻는다:
- 어떤 일을 하나요? (직무/업무 성격)
- 매일·매주 반복되는 작은 작업 3가지는?
- 지금 Claude Code로 해보고 싶은 것 하나는?

답은 ①-4(개인화)와 ③의 4주 자동화 로드맵에서 쓴다.

**①-4. CLAUDE.local.md 개인화 초안 제안**
- ①-3 답을 바탕으로 `CLAUDE.local.md`에 참가자의 업무 맥락을 담을 짧은 문단 초안을 **제안만** 한다.
- 예: "나는 ~한 업무를 하고, 반복 작업은 ~이다. skill은 ~에 초점을 둔다."
- 참가자가 원하면 함께 반영하고, 원치 않으면 그대로 둔다. (①-2의 정체성 블록 아래에 업무 맥락만 얹는다 — 성함·목적을 다시 묻지 않는다. 여전히 `CLAUDE.md`가 아니라 `CLAUDE.local.md`에 쓴다.)

**①-5. 시스템 감지 + 설정**
- OS를 감지하거나 확인이 안 되면 짧게 묻는다 (macOS / Windows). bash를 전제하지 않는다.
- 참가자는 Claude Code 기본 사용 경험이 있다고 전제하되, 막히면 필요한 부분만 설명한다.
- 마켓컬리 실습 전에 Node 18 이상과 인터넷 연결을 확인한다. 확인 방법이나 OS별 설치 안내가 필요하면 `reference/setup-guide.md`를 읽는다.
- Windows/Mac 터미널 차이나 Python이 필요해지면 같은 가이드를 참고한다. 평소에는 읽지 않는다.
- Claude Code 설정(`.claude/settings.json`, 권한, hooks 등)이 필요하면 직접 고치지 않고 **`/update-config`를 실행하도록 안내**한다.

**①-6. git init + 첫 커밋** (미초기화 시)
- 되돌리기 어려운 작업이므로 반드시 순서를 지킨다: **감지 → 제안 → 동의 확인 → 실행.**
- 제안 예시: "기존 clone 히스토리를 지우고 이 폴더를 참가자님 개인 git 저장소로 새로 시작할게요 (`git init` + 첫 커밋). 진행할까요?"
- 커밋 전에 `.gitignore`에 `/CLAUDE.local.md`가 있는지 확인한다 — 템플릿에 이미 있어야 정상이지만, 없으면 먼저 추가한다. 개인 정보가 git 이력에 남는 걸 막는 안전장치다.
- 동의를 받으면 기존 `.git`을 로컬에서만 재초기화하고 지금까지 만든 파일로 첫 커밋을 만든다. `CLAUDE.local.md`(정체성·업무 맥락)는 `.gitignore` 덕에 이 커밋에 자동으로 안 실린다 — 의도된 동작이다.
- **GitHub 원격 저장소 생성은 이 단계에서 하지 않는다** (`gh` 인증이 필요해 실습 시간을 예측하기 어렵다). 원격이 필요하면 참가자가 이후 직접 만들도록 안내만 한다.

### ② 실제 장보기 + 첫 skill (10~25분)

이 단계에서는 `reference/grocery-mission.md`를 읽고 그대로 진행한다.

1. **환경과 설치 확인**
   - Node 18 이상과 인터넷 연결을 확인한다. 안 되면 `reference/setup-guide.md`의 최소 대체 경로를 따른다.
   - k-skill 플러그인을 아래 두 명령으로 설치하게 한다. 첫 번째만 실행하고 끝내지 않는다.
     ```text
     /plugin marketplace add NomaDamas/k-skill
     /plugin install k-skill@k-skill
     ```
   - k-skill 저장소를 별도로 clone하지 않는다.
2. **장보기 조건 선택**
   - 장보기 미션 A~C 중 하나를 고르게 한다. 인원·식단·예산·제외 조건은 참가자가 바꿀 수 있다.
3. **라이브 검색**
   - `/k-skill:market-kurly-search`로 품목별 실제 상품을 검색한다.
   - 검색 결과에 없는 가격·할인·재고·배송을 추정하지 않는다.
   - 상품 URL이 있는 후보만 최종 표에 넣고 루트 `grocery-result.md`에 저장한다.
   - DEMO 경로를 썼다면 이후 흐름은 파일 형식 연습일 뿐이다. 라이브 결과로
     `grocery-result.md`를 덮어쓰고 장보기 skill을 실제 실행하기 전에는 1주차 완료로 세지 않는다.
4. **내 skill로 만들기**
   - 같은 과정을 반복하는 `.claude/skills/{참가자가 정한 이름}/SKILL.md`를 만든다. 기본 이름은 `my-grocery-planner`로 제안한다.
   - 이 skill은 인원·식단·예산·제외 조건을 받고, 라이브 검색 후 `grocery-result.md`를 갱신하도록 한다. 가격이나 상품을 SKILL.md에 고정하지 않는다.
   - “장보기 도와줘” 같은 트리거로 실제 한 번 실행해 결과를 확인한다.
   - 결과 수정·재실행은 시간이 남을 때만 한다. 첫 실행이 실제 상품 URL을 담고 있으면 다음 단계로 간다.

이 장보기 skill은 1주차 첫 skill로 인정한다. 이후 계속 쓸지 접을지는 참가자가 정한다.

### ③ 내 업무 + 실제 사례 + 4주 로드맵 HTML (25~37분)

1. ①에서 확보한 업무 맥락을 다시 묻지 말고, **4주 동안 해결하고 싶은 반복 업무나 만들고 싶은 자동화 하나**만 확인한다.
2. `data/README.md`와 각 파일의 제목·태그·핵심 요약으로 후보를 먼저 좁힌다. 원문 전문 63개를 통째로 읽지 않는다.
3. 관련성이 높은 사례 2~3개만 열어 참가자의 목표와 닮은 점, 빌릴 점, 버릴 점, 원문 URL을 뽑는다.
4. `reference/automation-roadmap-template.html`을 읽고 루트 `automation-roadmap.html`로 채운다.
   - 참가자 입력과 사례 텍스트는 HTML escape한다.
   - week-1은 오늘 만든 장보기 skill로 쓴다.
   - week-2~4는 참가자 목표를 향한 작은 가설·후보로 쓰고 아직 만들지 않은 skill을 확정 약속처럼 표현하지 않는다.
   - 사례는 실제로 읽은 2~3개만 넣고 원문 URL을 클릭 가능한 링크로 남긴다.
   - `{{next_step}}`에는 라이브 장보기까지 끝났으면 `다음 단계: 2주차`, DEMO라면
     `다음 단계: 장보기 라이브 검색`을 넣는다.
5. 생성 직후 `reference/roadmap-html-validation.md`를 읽고 빠른 검사를 통과시킨 뒤 브라우저로 연다. 자동으로 열 수 없으면 파일 링크와 위치를 알려준다.

### ④ OT 초안 + 2주차 핸드오프 (37~50분)

1. 장보기 검색, 만든 skill, 첫 실행 결과를 `g23-case-writer`에 넘겨 **OT 사례 게시글 초안**을 만든다.
   - 수정·재실행을 안 했다면 고친 점을 지어내지 않는다.
   - 50분 필수 완료선은 초안이다. gpters.org 로그인과 실제 발행은 시간이 남을 때만 참가자가 직접 한다.
2. 오늘 손에 남은 것을 한 화면으로 요약한다.
   - 장보기 skill 경로
   - `grocery-result.md`
   - `automation-roadmap.html`
   - OT 사례 게시글 초안
3. 다음 행동을 한 문장으로 준다.
   - 라이브 검색과 장보기 skill 실행을 마쳤다면:
     > 이제 **“2주차 미션 알려줘”** 라고 말해보세요. `g23-missions`가 로드맵의 다음 작은 행동과 연결해 안내해요.
   - DEMO만 했다면 2주차로 넘기지 않는다:
     > 오늘은 파일 흐름까지 연습했어요. Node 18과 인터넷을 확인한 뒤 **“장보기 실습 다시 이어줘”**라고 말해보세요. 실제 상품 URL을 확인하면 1주차를 마무리할 수 있어요.

## 하지 말 것
- `.claude/settings.json`, hooks, 권한 설정을 자동으로 만들거나 수정하지 않는다 — `/update-config`로 넘긴다.
- 동의 없이 `git init`/히스토리 재작성을 실행하지 않는다.
- GitHub 원격 저장소를 자동으로 만들거나 push하지 않는다.
- 정체성·업무 맥락을 `CLAUDE.md`(스터디 공용 가이드)에 쓰지 않는다 — 개인 정보는 항상 `CLAUDE.local.md`.
- ①-3(업무 파악) 답을 참가자 대신 해석해 `CLAUDE.local.md`에 바로 쓰지 않는다 — ①-4는 제안만 하고 동의를 받는다.
- 이미 확보된 정체성·업무 맥락을 다시 묻지 않는다 (①-1 감지 결과를 따른다).
- 참가자가 요청하지 않은 파일을 대량 생성하지 않는다. 첫날 산출물은 장보기 skill,
  `grocery-result.md`, `automation-roadmap.html`, OT 초안으로 한정한다.
- OS나 요금제를 넘겨짚지 않는다. 모르면 묻는다.
- `data/*.md` 63개의 원문 전문을 통째로 읽지 않는다. 인덱스·태그·요약으로 좁힌 뒤 2~3개만 읽는다.
- HTML에 외부 CSS·JavaScript·폰트·이미지를 추가하거나 `{{...}}` placeholder를 남기지 않는다.
- 수정·재실행을 하지 않았는데 사례글에 고친 점이나 개선 효과를 지어내지 않는다.
- 참가자를 대신해 gpters.org에 발행하지 않는다.
