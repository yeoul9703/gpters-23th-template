# 4주 자동화 로드맵 HTML 검증

> `g23-welcome`이 `automation-roadmap.html`을 만든 직후 빠른 검사를 할 때 읽는다.
> 템플릿을 출시하기 전에는 아래 전체 항목을 데스크톱·모바일 렌더로 다시 확인한다.

## 매번 생성 직후 빠른 검사

1. **미완성 표시 없음**
   - `{{` 또는 `}}` placeholder가 0건이어야 한다.
   - `확인 필요`, 빈 제목, 빈 링크가 남으면 참가자에게 확인하거나 해당 선택 항목을 지운다.
2. **콘텐츠 계약**
   - `내가 하고 싶은 것`, `관련 지피터스 사례`, `1~4주 자동화 로드맵`이 모두 있다.
   - 사례는 2~3개다. 각 사례에 제목·선정 이유·빌릴 점·버릴 점·원문 URL이 있다.
   - week-1은 오늘 실제로 만든 장보기 skill이고, week-2~4는 확정 약속이 아닌 가설·후보다.
   - 라이브 장보기까지 끝났으면 `다음 단계: 2주차`, DEMO라면
     `다음 단계: 장보기 라이브 검색`으로 표시한다. DEMO HTML이 2주차 완료를 암시하지 않는다.
   - 참가자가 바로 이해할 수 있는 일상어를 우선하고, 필요한 전문용어는 짧게 풀어 쓴다.
   - 단정하거나 재촉하는 표현보다 `먼저 ~해봅니다`, `~부터 시작해볼 수 있어요`,
     `부담 없이 하나씩`처럼 시도할 여지를 주는 쿠션어를 쓴다. 다만 과장된 격려나
     확인하지 않은 효과는 덧붙이지 않는다.
3. **링크 계약**
   - 사례 링크는 `https://www.gpters.org/` 또는 `https://gpters.org/` 원문 URL이다.
   - `<a href="..." target="_blank" rel="noopener noreferrer">`로 클릭 가능하다.
4. **GPTERS 색상 계약**
   - `#eb5a10`, `#d34600`, `#fff5f1`, `#ffe0d1`, `#060607`, `#525458`,
     `#f6f6f6`, `#ffffff`, `#f3f3f3`, `#e9e9e9`가 CSS custom properties에 있다.
   - 외부 CSS·JavaScript·폰트·이미지를 추가하지 않는다.
5. **사실성**
   - 참가자가 말하지 않은 목표·효과·숫자를 지어내지 않는다.
   - `data/`에서 실제로 읽은 2~3개 사례만 쓴다.
   - 참가자 입력과 사례 텍스트의 `<`, `>`, `&`, `"`를 HTML escape해 문서 구조를 깨지 않는다.

## 출시 전 렌더 검사

대표 샘플 데이터로 템플릿을 채운 뒤 브라우저에서 아래 두 크기를 확인한다.

- 데스크톱: 1440×900
- 모바일: 390×844

두 화면 모두에서 다음을 만족해야 한다.

- 가로 스크롤이 없다: `document.documentElement.scrollWidth <= window.innerWidth`
- 제목·본문·카드가 겹치거나 잘리지 않는다.
- 사례 링크가 보이고 새 탭 링크의 URL이 원문과 일치한다.
- 키보드 Tab으로 링크에 이동했을 때 focus 표시가 보인다.
- 색상 없이 읽어도 `빌릴 점`·`버릴 점`·주차를 텍스트로 구분할 수 있다.
- `<h1>`은 1개이고, 문서 순서는 `h1 → h2 → h3`로 자연스럽다.
- 브라우저 콘솔 오류가 없다.

템플릿 자체만 보고 통과 처리하지 말고, 실제로 placeholder를 채운 산출물을 렌더해
판정한다.
