# 첫날 장보기 미션

> `g23-welcome` ②에서만 읽는다. 가격·할인율·상품 목록은 저장하지 않고 실습 때
> `/k-skill:market-kurly-search`로 새로 조회한다.

## 고르는 법

아래 A~C 중 하나를 고른다. 참가자가 원하면 인원·식단·예산·제외 조건만 바꿔도 된다.
검색 품목은 3개를 기본으로 하고, 시간이 부족하면 2개로 줄인다.

### A. 1인 아침 장보기

- 인원: 1명
- 식단: 그릭요거트 볼과 간단한 아침
- 검색 품목: 그릭요거트, 그래놀라, 바나나
- 예산: 30,000원 이내
- 선택 조건: 1~2주 안에 먹을 수 있는 양을 우선

### B. 2인 저녁 장보기

- 인원: 2명
- 식단: 닭고기 카레와 샐러드
- 검색 품목: 닭가슴살, 카레, 샐러드 채소
- 예산: 40,000원 이내
- 선택 조건: 조리 시간을 줄일 수 있는 상품을 우선

### C. 4인 주말 아침 장보기

- 인원: 4명
- 식단: 달걀·치즈 샌드위치와 우유
- 검색 품목: 식빵, 달걀, 슬라이스 치즈
- 예산: 50,000원 이내
- 선택 조건: 품절 상품은 대체 상품을 함께 제안

## 라이브 검색 결과에 반드시 남길 것

품목별로 아래 정보를 `grocery-result.md` 표에 남긴다.

- 상품명
- 조회 시점
- 현재 가격
- 할인 정보(없으면 `할인 없음`)
- 품절 여부
- 배송 정보(검색 결과에 있을 때만, 없으면 `확인 필요`)
- 실제 상품 URL
- 이 상품을 고른 이유 한 줄

정보가 검색 결과에 없으면 지어내지 말고 `확인 필요`로 쓴다. URL 없는 후보는 최종
장보기 표에서 제외한다.

위 규칙은 **라이브 검색에 성공했을 때의 최종 결과 계약**이다. 환경 문제로
`reference/setup-guide.md`의 DEMO 경로를 쓸 때만 URL 없는 진단용 표를 잠시 허용한다.
DEMO 표는 최종 장보기 결과나 1주차 완료로 세지 않고, 환경을 복구한 뒤 라이브 검색
결과로 덮어쓴다.

## 장보기 skill 최소 계약

기본 이름은 `my-grocery-planner`로 제안하되 참가자가 바꿀 수 있다.

- 트리거 예시: “장보기 도와줘”, “이번 주 장보기 목록 만들어줘”
- 입력: 인원, 식단, 예산, 제외 조건
- 처리: 필요한 품목을 정하고 각 품목을 `market-kurly-search`로 라이브 검색
- 출력: 위 필드를 가진 장보기 표를 루트 `grocery-result.md`에 저장
- 금지: 가격·재고·배송 정보를 SKILL.md에 고정하거나 검색하지 않은 값을 추정
