# skill-creator — 3문 인터뷰로 SKILL.md 한 장

skill 하나 = `.claude/skills/{skill-name}/SKILL.md` 파일 **한 장**이다.
이 skill은 질문 3개로 그 한 장을 만든다. 스크립트도, 보조 파일도 만들지 않는다.

## 진행 순서 (5단계)

### 1. 범위 확인 — 만들 준비가 됐나?

만들려는 게 한 문장으로 나오는지 먼저 확인한다:
**"[언제] [무엇을 입력]하면 [무엇을 출력]한다."**

- 한 문장이 안 나오거나 후보가 여러 개면 → 만들지 말고 이렇게 안내한다:
  **"아직 흐릿하면 `g23-thinking-partner` 부터 — 미니 스펙(뭘 하나·트리거·15분 범위)을 먼저 만들고 돌아오자."**
- `g23-thinking-partner`에서 미니 스펙을 들고 왔으면, 2단계 질문의 답이 이미 있다.
  같은 걸 다시 묻지 말고 "이 스펙대로 만들면 될까?" 확인만 한다.

### 2. 3문 인터뷰

한 번에 하나씩 묻는다. 참가자의 말을 그대로 받아 적는다.

1. **뭘 하나?** — 무엇을 넣으면(입력) 무엇이 나오나(출력). 예: "회의 메모를 주면 → 결정사항·할 일 목록이 나온다"
2. **언제 켜나?** — 이 skill을 쓰고 싶을 때 실제로 할 법한 말 3~5개. 예: "회의 정리해줘", "미팅 메모 요약"
3. **특수한 도구가 필요한가?** — 파일을 읽거나, 터미널 명령을 돌려야 하나? 모르겠으면 "없음"으로 시작해도 된다.
   - 답이 "Python 스크립트/라이브러리가 필요하다"이면 `../g23-welcome/reference/setup-guide.md` §2(uv 컨벤션) 참고 — 이 경우가 아니면 평소엔 읽지 않는다.

### 3. SKILL.md 초안 생성

`.claude/skills/{skill-name}/SKILL.md` 한 장을 만든다.

- **frontmatter** (파일 맨 위 `---` 두 줄 사이의 정보 블록):
  - `name`: 영문 소문자와 하이픈(-)만. 예: `meeting-note-cleaner`
  - `description`: **가장 흔한 쓰임을 첫 문장에**, 그 뒤에 2번 답의 트리거 표현을 **약간 넉넉하게** 넣는다 (적게 넣으면 안 켜지는 쪽이 더 흔한 실패다). 전체 1,536자 이내.
- **본문**: 무엇을 어떤 순서로 하는지, 입력·출력 형태. 500줄 이하가 규칙이지만 보통 30~60줄이면 충분하다.
- 파일은 이 한 장뿐. 다른 파일을 만들지 않는다.

### 4. 트리거 자가확인

"이렇게 말하면 켜질까?" 문장 3~5개를 참가자와 함께 눈으로 점검한다 (도구나 스크립트 없이).
안 켜질 것 같은 표현이 있으면 description에 그 표현을 추가한다.

### 5. 한 주 써보고 고치기

"skill 고치자", "skill 수정"이라고 하면 기존 SKILL.md를 읽고 묻는다:
- 안 켜졌나? → description에 실제로 썼던 말을 추가
- 결과가 이상했나? → 본문에서 애매했던 순서·형식 한두 줄 수정

고치는 건 보통 **한두 줄**이다. 크게 다시 쓰지 않는다.
고친 내용은 g23-case-writer가 안내하는 사용 기록 형식으로 짧게 기록하면 사례글 쓸 때 재산이 된다.

## 원칙

- 참가자 대신 결정하지 않는다. 이름·트리거·범위 모두 후보를 주고 고르게 한다.
- 첫 버전은 작게. "15분 안에 만들 수 있는 범위"를 넘으면 `g23-thinking-partner`로 되돌려 쪼갠다.
- 더 본격적인 공식 도구가 궁금하면: `skill-creator@claude-plugins-official` 플러그인이 있다 (이 스터디에서는 이 가벼운 한국어판을 쓴다).
