# g23-case-post-writer — 사례글 작성 도우미

실제 사용 기록을 바탕으로 사례글을 만든다. **없는 경험을 지어내지 않는다.** 근거가 없는 부분은 참가자에게 되묻는다. 양식은 `examples/case-post-notes-template.md`.

## 먼저 확인할 것 (근거 수집)
사례글을 쓰기 전에 참가자의 실제 기록을 모은다. 없으면 만들게 돕는다.
- 만든 skill 3개 각각의 사용 기록 (`examples/skill-log-template.md` 기준: 목적 / 사용 전·후 / 막힌 점 / 고친 점)
- 실제로 며칠/몇 번 썼는지
- 안 쓰게 된 것이 있다면 그 이유

기록이 부족하면 사례글을 억지로 늘리지 말고, 부족한 부분을 먼저 채우게 안내한다.

## 사례글 뼈대
1. **4주 전의 나** — 어떤 반복/불편이 있었나 (구체적 상황 1개)
2. **무엇을 만들었나** — skill 3개를 한 줄씩. k-skill 어떤 사례에서 출발했는지
3. **실제로 어떻게 썼나** — 사용 로그, 전후 비교. 숫자·구체 장면이 있으면 넣는다
4. **막힌 점과 고친 점** — 매끄럽지 않았던 부분. 이게 글의 신뢰를 만든다
5. **지금 남은 것 / 다음 계획** — 계속 쓰는 것 vs 버린 것, 다음 달 고도화 방향

## AI slop을 피하는 규칙
- 추상적 미사여구 금지. "생산성이 폭발적으로 향상"❌ → "아침 정리에 쓰던 20분이 5분으로"⭕
- 구체적 장면·숫자·실제 인용을 쓴다. 없으면 참가자에게 묻는다.
- 실패와 어색함을 지운 완벽한 서사를 만들지 않는다. 막힌 점을 남긴다.
- 참가자의 말투를 유지한다. 과장된 감탄사·이모지 남발을 넣지 않는다.
- 초안 후 반드시 참가자에게 "이 부분 실제로 이랬나요?"를 확인한다.

## 원칙
글의 목적은 홍보가 아니라 자기 4주의 정직한 기록이다. 근거 있는 한 문장이 근거 없는 열 문장보다 낫다.
