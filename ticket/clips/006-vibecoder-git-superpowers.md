## 왜 클립했나 (한 줄)

"명령은 AI가 치고 사람은 선택만 한다"는 원칙으로 깃을 모르는 바이브코더도 안전하게 협업하는 구조를 해부한 글.

## 핵심 요약

- 깃허브 스타 20만의 superpowers 플러그인을 분석: worktree 작업 격리 → 테스트 확인 → 별도 리뷰어 검수 → 지적 반영의 네 가지 규칙이 GitHub Flow 위에서 돌아감.
- 테스트 후 머지/PR/보존/폐기 4가지 선택지를 사람에게 제시하는 흐름.
- 운영 중 발견한 함정 3가지(무비판적 승인, 자동 감지 안 되는 로직 에러, 중복 격리)까지 정리.

## 원문 발췌

- "깃허브에서 권하는 GitHub Flow가 이 방식의 가벼운 버전입니다. main에서 브랜치 따고, PR 올리고, 리뷰받고, 합치고, 배포. 그게 다예요."
- "이렇게 쓰다 보니 제가 superpowers한테 배운 건 깃 명령어가 아니었어요. 시작 전에 폴더를 갈라놓고, 끝에서 테스트로 확인하고, 합치기 전에 다른 눈으로 한 번 더 보게 하는 순서였습니다."

## 내 업무에 어떻게 쓸까

여러 작업을 동시에 굴릴 때 worktree 격리 + 머지 전 별도 리뷰어 검수 패턴을 도입할 것. "AI가 시키는 대로 승인만 하는 함정"은 체크리스트에 명시해둘 것.

## 글쓰기에서 훔칠 점

- "저는 Rona 같은 AI 코딩 도구를 만듭니다. 일은 거의 Claude Code로 해요." — 자기소개 두 문장으로 신뢰와 맥락을 동시에 세팅.
- "결제 금액 고치다가 동료가 먼저 알림 기능 병합" 같은 충돌 시나리오를 구체 사례로 제시.
- 도구 예찬으로 끝내지 않고 함정 3가지를 별도 섹션으로 — 균형 잡힌 리뷰 구조.
