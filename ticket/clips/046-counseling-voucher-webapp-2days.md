## 왜 클립했나 (한 줄)

코딩 전에 "규칙 문서부터" 하루를 쓴 순서가 인상적 — CLAUDE.md/규칙 작성을 먼저 시키는 스터디 커리큘럼의 근거 사례.

## 핵심 요약

- 비개발자 자동화 담당자가 Claude Code + Supabase + Vercel로 2일 만에 상담센터 바우처 행정 웹앱을 배포.
- 1일차는 규칙 문서 작성(추정 금지·개인정보 보호·최종 확정은 사람), 2일차에 가짜 데이터 5단계 프로토타입 → DB 전환 → 배포.
- "내담자 1명=상담사 1명"이라는 초기 설계 오류를 실무진 피드백으로 발견, "내담자×바우처" 구조로 반나절 만에 갈아엎음.

## 원문 발췌

- "제일 큰 고비는 코딩이 아니었어요 — 실무진의 업무를 제가 요약해서 AI한테 전달하는데, 그 요약이 현장과 달라서 화면 다 만든 뒤에 데이터 구조를 갈아엎었어요"
- "AI가 틀린 게 아니에요. 실무진의 업무를 AI한테 전달하는 중간에서, 제가 잘못 요약한 거예요."

## 내 업무에 어떻게 쓸까

"규칙 문서 먼저 → 가짜 데이터 프로토타입 → 실데이터" 3단계 순서를 참가자 웹앱형 skill 가이드로 정리. "실무진의 한 문장이 기획 열 줄보다 정확했다"는 인용도 소개용으로.

## 글쓰기에서 훔칠 점

- 제목이 곧 요약(누가/얼마 만에/무엇을)인 정직한 도입.
- 실무자 목소리를 직접 인용해 현장감을 만드는 기법.
- "화면 다 만든 뒤에 데이터 구조를 갈아엎었어요" — 실수를 장면으로 보여주는 문장.
