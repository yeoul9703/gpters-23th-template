## 왜 클립했나 (한 줄)

"프롬프트 한 방"에서 "스스로 도는 시스템"으로 넘어가는 프레임 전환을 6개 부품으로 깔끔하게 분해한 개념 글.

## 핵심 요약

- 루프 엔지니어링 = 에이전트가 스스로 작업을 발견·실행·검증하게 시스템을 설계하는 것 (애디 오스마니 제안).
- 6가지 부품: 자동 실행 / 작업 격리(worktrees) / 맥락 문서화(Skills) / 외부 연동 / 역할 분리 / 외부 기억. 핵심은 검증을 별도 에이전트가 맡는 것.
- 효과: 의도 빚(반복 설명 비용)과 이해 빚(지식 격차) 감소. Claude Code `/goal`로 검증 조건을 다른 모델이 판정하는 예시.

## 내 업무에 어떻게 쓸까

028번(실전 적용기)과 짝지어 "개념 → 실전" 세트로 스터디 3~4주차 읽기 자료로. skill에 검증 단계를 분리하는 구조의 이론적 근거.

## 글쓰기에서 훔칠 점

- "한줄 요약" → "무슨 일이 있었나" 순서의 뉴스레터식 골격.
- 전문가 인용("더 이상 프롬프트하지 않는다")을 훅으로 쓰고 바로 풀어 설명하는 리듬.
