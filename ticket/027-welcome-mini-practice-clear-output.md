## 뭘 하려는가 (한 줄)

`g23-welcome` ⑤ 미니 실습의 "성공" 기준을 **트리거 발동 여부**만이 아니라
참가자가 눈으로 확인할 수 있는 **명확한 아웃풋**이 실제로 나오는지까지로 강화한다.

## 왜 / 언제 쓰는 일인가

방금 021에서 ⑤ step1·2(세 시점 질문 구체화, 예시 코드 3개)를 다듬었지만,
step3의 "성공" 정의는 여전히 다음과 같다:

> 만든 직후 트리거 문장을 말해 바로 한 번 실행해 본다. 켜지면 그게 첫 성공이다.

이건 스킬이 **실행됐다는 것만** 확인하고, 실제로 쓸 만한 결과물이 나왔는지는 보지 않는다.
온보딩 목적이 "5분 안의 첫 성공 경험"인데, 트리거는 됐지만 답이 애매하거나 부실하면
체감 성공이 약해질 수 있다 — 사용자 지적: "미니 실습은 명확한 아웃풋이 나올 수 있어야 한다."

## 결정된 것 (2026-07-04, 사용자 확인)

- **"명확한 아웃풋" = 파일로 남는 산출물 + 효용감.** 021에서 만든 3개 커스텀 예시(아침 킥오프/오후 리포커스/퇴근 전 정리)는 SKILL.md 파일 자체는 남기지만, **실행 결과**(예: "오늘 할 일 우선순위 3개")는 채팅 응답으로만 나오고 파일로 안 남는다 — 이 실행 결과까지 산출물로 볼지가 쟁점이었음.
- step3 "성공" 정의는 아래 재결정 반영해 자연스럽게 정한다 (트리거 발동 + 산출물 확인).

## 결정된 것 (2026-07-14, 재검토 — welcome 전체 흐름 정합성 점검)

전체 흐름 재확인: `invoke → 스킬 선언 → (구 setup 흡수, ①~④) → 1주차 OT용 k-skill 체험 + 만든 skill 체험 → g23-case-writer로 사례 작성/발간 안내`.
이 흐름은 **k-skill 체험과 만든 skill 체험이 둘 다** 있어야 완성된다. 07-04 안(커스텀 예시를 실제 k-skill로 **교체**)은 이 중 "만든 skill 체험"을 없애버려 흐름과 어긋남 → 아래로 뒤집음.

- **교체 아님, 추가.** ⑤ 커스텀 미니 실습(021, 하루 세 시점 예시 3개)은 **그대로 유지**한다. 대신 **② k-skill 준비** 단계에 "실제로 k-skill 하나를 설치하고 실행해보는" 체험 task를 새로 추가한다 (지금 ②는 "레포 둘러봤는지 확인 + 설치 안내"뿐, 실제 실행이 없음).
- **전체 온보딩 예산 ~50분.** 프로젝트 설치·셋팅(①)부터 k-skill 체험(②)·업무파악(③)·CLAUDE.md 개인화(④)·미니 실습(⑤)까지 이 예산 안에 들어가야 함. ⑤ 자체의 "5분 안에" 목표는 유지하되, 전체 합산이 50분을 넘지 않게 페이싱 참고.
- **"하루 세 시점"(아침/점심/퇴근)은 필수 구조가 아니라 스터디장(사용자)이 쓰는 예시·팁 수준.** SKILL.md에서 이게 강제 규칙처럼 읽히지 않도록 다듬는다. 본질은 "k-skill과 직접 만든 skill로 실무자의 반복 업무 자동화를 실제 경험하게 하는 것" — 세 시점 프레이밍에 과하게 맞추려 하지 않는다.
- **`k-skill-researcher`는 지금 그대로 충분.** README 기반으로 후보를 넓게 훑어오는 가벼운 조사 전담 에이전트라 추가 플로우 설계 불필요. 호출 시 "무엇을 하는 에이전트인지" 한 줄 설명만 곁들이면 됨.
- 적용 범위: **welcome ②·⑤.** skill-creator 범위 확인 단계엔 반영 안 함.

## 결정된 것 (2026-07-14, ② 실습 설계 확정)

- **② 체험용 k-skill 후보 확정: `market-kurly-search`.** `k-skill-researcher` 조사 결과(당근마켓/마켓컬리/다나와/쿠팡/오늘의집 5개 후보) 중 "오늘의 음식 핫딜" + 자격증명 불필요 + 직군 무관 조건에 가장 부합.
- **"지피터스 사례에서 반응 좋은 물건" 조사는 폐기.** 로컬 클립 51개 키워드 스캔 결과 장보기/식품 관련 신호 없음(구독 5건은 전부 SaaS 구독료 얘기로 무관). → 아이템은 임의 선정으로 대체.
- **예시 아이템 4개 제시 + 자유 검색 허용.** 생수 / 원두커피 / 우유 / 계란 중 하나로 해봐도 되고, 원하는 다른 품목을 검색해도 된다고 안내.
- **② 흐름 = "설치 → 바로 실행"으로 한정.** `market-kurly-search`는 이미 완성된 k-skill이라 설치(`/plugin marketplace add NomaDamas/k-skill`) 후 `/k-skill:market-kurly-search` 실행 → 결과 확인만으로 끝낸다.
- **`k-skill-researcher`·`skill-creator`를 ②에 재동원하지 않는다.** 이미 있는 걸 다시 리서치해서 skill-creator로 재창작하면 (a) 50분 예산을 잡아먹고 (b) "직접 만드는" 만족감을 ⑤(thinking-partner→skill-creator, 본인 반복 업무 기반)에서 미리 소진시켜 버림 — 채택 안 함. `k-skill-researcher`는 이번 후보 선정(오프라인 리서치)으로 역할 종료, `skill-creator`는 ⑤ 전용으로 유지.

## 후보 조건 (② 체험용 k-skill 조사 시 기준)

- 짧게 끝날 것 — ② 안에서 체험하는 용도라 전체 50분 예산을 침범하면 안 됨.
- **파일 등 durable artifact를 실제로 남길 것** (채팅 응답만으로 끝나면 탈락).
- **자격증명/API 키 설정이 필요 없을 것** — 첫 체험에서 별도 셋업이 끼면 안 됨(`k-skill-setup` 필요한 스킬은 제외).
- 직군 무관하게 통할 것 (하루 세 시점 프레이밍에 억지로 맞출 필요 없음).
