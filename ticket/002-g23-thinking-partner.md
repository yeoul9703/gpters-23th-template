## 뭘 하려는가 (한 줄)

"뭐 자동화하지"처럼 흐릿한 상태를, 또렷한 미니 스펙(뭘·트리거·15분 범위)까지 좁혀준다.

## 왜 / 언제 쓰는 일인가

이미 `.claude/skills/g23-thinking-partner/` 존재 → **개선 티켓**.
목적지가 있는 사고 파트너: 명확해지면 **skill-creator 로 핸드오프**(생성은 거기 담당).

트리거: "skill 뭐 만들지", "아이디어가 없어", "범위 좁혀줘", "이거 skill 될까", "반복 업무"

## 확정된 설계 (덩어리 B)

**레퍼런스에서 취사선택**
- `grilling`(vmc) 차용: **한 번에 한 질문 + 각 질문에 추천 답 동봉**(비개발자 막힘 방지),
  결정 의존성 하나씩 해소. 단 "relentless"는 뺌 — 바쁜 실무자용, 질문 수 최소.
- `thinking-partner`(Rhim80) 차용: 질문 우선, 가정 부드럽게 짚기,
  "지금까지 나온 것" 주기 요약, 종료 시 다음 스텝 제안.
- **덜어냄(P1)**: 노트 워크스페이스 탐색(30-knowledge 등, 우리엔 없음), 무한 grilling, 인사이트 트래킹 파일.

**흐름 (대화형, 파일 하나)**
1. 하고 싶은 걸 한 줄로 받기 (흐릿해도 OK)
2. **한 번에 한 질문 + 추천 답**으로 좁히기: 어떤 반복 업무? / 입력→출력? / 언제 켜지면(트리거)?
3. 가정 짚기: "이거 매주 진짜 반복돼요?" 부드럽게
4. "지금까지 나온 것" 요약 → **15분 범위로 자르기** (크면 쪼갬)
5. 또렷하면 → "이제 skill-creator 로 만들자" 핸드오프. 아직 흐릿하면 질문 더.

**B2 경계 (확정)**: 명확화·범위 = thinking-partner / 생성 = skill-creator. (005 step1 과 일치)
