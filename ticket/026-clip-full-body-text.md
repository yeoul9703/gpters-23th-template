### 2026-07-14 최종 해결 (같은 날 후속 세션, 사용자 지시로 재개)

사용자 방향: "curl .sh가 문제의 뿌리 — uv venv를 setup이 관리한다는 가정으로 Python으로 재작성." 위 재오픈 메모의 selector 가설이 그대로 해법이 됐다.

**해법 (bash 2개 삭제 → `scripts/fetch_post.py`·`fetch_list.py` 신설):**

- **uv 실행**: PEP 723 인라인 의존성(requests)으로 `uv run <경로> "<url>"` 한 줄 실행. venv 수동 세팅 불필요 (setup-guide §2 uv 컨벤션).
- **셸 오염의 근본 해결**: Jina Reader에 `x-target-selector: article.prose` 헤더 — 문자열 패턴으로 셸을 "걸러내는" 대신 본문 요소만 "가져온다". 헤더/네비/footer/추천글/뉴스레터가 애초에 응답에 없다.
- **셀렉터 실측 2건**: ① `div.basis-full > article.prose`처럼 좁히면 헤딩·이미지·링크가 형제 블록인 글(035)에서 본문이 소리 없이 유실 → 넓은 `article.prose` 채택, 대신 댓글 텍스트가 여분으로 붙을 수 있음(조용한 유실 < 여분 포함). ② 없는 URL은 Jina가 JSON 422를 줘서 죽은 링크 판정이 명확해짐. member 프로필류는 URL 패턴(`/post/` 필수)으로 차단.
- **429 rate limit**: Jina 무료 티어 ~20 RPM. retryAfter 대기 재시도 + 백필 시 호출 간 4초 간격으로 해소.
- **013 손상 유형의 구조적 방지**: 원문 전문을 3-backtick이 아니라 **4-backtick 펜스**로 감싼다(본문 내 ``` 코드블록과 충돌 없음). 백필 교체도 정규식이 아니라 줄 단위 섹션 경계 스캔으로.

**결과**: 51/51 재백필 완료, 전수 검증 clean (섹션 존재·펜스 짝·순서·최소 길이·셸 마커 부재). 013 구조 손상, 016/021/043 "로그인 필요" 오표기 모두 이 재백필로 복구. 035는 Jina 렌더 비결정성(같은 요청이 시점 따라 부분판 반환, 헤더로 제어 불가 — 실측)으로 부분판이 잡혀서, 앞서 확보해둔 완전판 스냅샷으로 채움.
