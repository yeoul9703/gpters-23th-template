# 1주차 — k-skill로 첫 번째 업무 skill 만들기

> 목표: 처음부터 새로 만들지 않고, k-skill 사례를 가져와 **실제로 동작하는 첫 skill**을 만든다.

## 함께 하는 것
- k-skill 구조 살펴보기 (`g23-k-skills-search`)
- 내 업무에서 반복되는 작은 문제 고르기 (`g23-thinking-partner`)
- 가장 비슷한 사례를 골라 내 상황에 맞게 바꾸기

## 이번 주 순서
1. `g23-welcome`으로 온보딩(초기 설정 + 미니 실습 + 미니 사례 발행)을 마친다. (처음이라면)
2. `g23-thinking-partner`로 내 반복 업무에서 후보 1개를 고르고 "[언제][입력]하면[출력]" 한 문장으로 만든다.
3. `g23-k-skills-search`로 비슷한 사례를 찾아 빌릴 점/버릴 점을 정리한다.
4. `skill-creator`로 `.claude/skills/{내-skill-이름}/SKILL.md`를 만들고, 실제로 한 번 써본다.
5. `examples/skill-log-template.md`로 사용 기록을 남긴다.
6. `g23-case-writer`로 이번 주 경험을 짧은 사례 게시글로 정리하고, gpters.org에 **`23기 [스터디]`** 태그로 발행한다.

## 손에 남는 것
- [ ] k-skill을 활용해 만든 **첫 번째 나만의 skill** 1개
- [ ] 그 skill의 사용 기록 1개
- [ ] gpters.org에 발행한 사례 게시글 1개 (`23기 [스터디]` 태그)

## 멤버 과제
만든 skill을 일주일 동안 써보고, **배운 점과 불편한 점**을 담은 사례 게시글을 gpters.org에 `23기 [스터디]` 태그로 발행합니다.

## 스터디장 사례글
- k-skill을 활용하여 나만의 아침이 달라진 사례

## 막히면
- 후보가 안 떠오른다 → `g23-thinking-partner`
- 딱 맞는 사례가 없다 → 도메인이 달라도 입력/출력 구조가 비슷하면 참고감이 됩니다
- 너무 커진다 → "15분 안에 끝낼 범위"로 다시 자르세요
