## 왜 클립했나 (한 줄)

"화면만"이 아니라 프론트-백-DB 3계층 배포까지 완주한 비전공자 사례 — 스터디의 '실제로 쓰는 결과물' 기준에 딱 맞는 레퍼런스.

## 핵심 요약

- 현직 공인중개사가 AI 페어 프로그래밍으로 To-Do 앱을 만들고 React+Vite(Vercel) / Node+Express(Heroku) / MongoDB Atlas 3계층을 연결해 실서비스로 배포.
- 개발자도구의 200 OK 응답 확인으로 "진짜 서비스" 완성을 스스로 증명.
- MongoDB 버전 오류, Atlas DNS 연결 실패, 배포 후 localhost 문제 등 막힌 지점과 해결책을 표로 정리.

## 원문 발췌

## **소개**

저는 개발 **비전공자, 현직 공인중개사**입니다. 매물접수·집보기·계약처럼 이동이 잦은 중개 업무를 그때그때 정리할 **'나만의 To-Do 앱'** 이 필요했고, AI 도구의 힘을 빌려 **직접 만들어보기로** 했습니다.

## **진행 방법**

**🛠 사용 도구**

*   AI 페어 프로그래밍: **Claude (Claude Code)** — 명령을 하나씩 주고받으며 코드 작성·오류 해결

*   프론트엔드: **React + Vite** / 백엔드: **Node.js + Express + Mongoose**

*   DB: MongoDB → **MongoDB Atlas**(클라우드) / 배포: **Heroku**(백엔드) + **Vercel**(프론트엔드)

**💡 활용 방식 — "한 단계씩 물어보고, 확인하고, 넘어가기"**

코드를 모르니 AI에게 _전체를 한 번에_ 시키지 않고, **작은 단위로 지시 → 결과 확인 → 다음 단계**로 진행했습니다. 비전공자에게는 이 방식이 핵심이었어요.

> 🖼️ **이미지 ①** — 완성된 To-Do 앱 메인 화면

📌 **이미지 설명:** 공인중개사 업무에 맞춰 만든 To-Do 앱의 메인 화면입니다. 상단에는 **'진행중 · 오늘 마감 · 완료'** 업무 현황이 한눈에 보이도록 숫자로 요약됩니다. 그 아래에는 검색창과 함께 **매물접수 · 광고관리 · 집보기 · 계약 · 잔금/중도금 · 서류 · 고객상담** 등 실제 중개 업무 흐름에 맞춘 카테고리 필터, **매매 · 전세 · 월세** 거래유형 필터, 마감일·우선순위 기준 정렬 기능을 넣었습니다. 각 할 일 카드에는 마감까지 남은 **D-day**, 카테고리, 우선순위, 마감일, 메모가 표시됩니다. _(개인정보 보호를 위해 실제 고객명·연락처·주소는 가렸습니다.)_

## **결과와 배운 점**

**🎉 결과**

**Vercel(프론트) → Heroku(백엔드) → MongoDB Atlas(DB)** 3계층이 클라우드에서 연결된 라이브 서비스를 완성했습니다. 개발자도구로 `200 OK` 응답까지 직접 확인했어요.

> 🔒 **라이브 링크는 보안상 공개하지 않습니다.**
> 
> 이 앱은 아직 **로그인 기능이 없어서**, 링크를 아는 누구나 데이터를 읽고·수정·삭제할 수 있습니다. 공개 게시물에 그대로 노출하면 **데이터가 오염될 위험**이 있어, 데모는 캡처 이미지로 대체했습니다.

**🧱 과정 중 시행착오 (가장 값진 학습)**

**문제**

**원인**

**해결**

MongoDB가 윈도우10에서 실행 안 됨 (오류 `0xC0000139`)

윈도우10이 최신(8.1+) 시스템 함수 미지원

**8.0 LTS** 버전으로 설치

Atlas 연결 시 `querySrv ECONNREFUSED`

Node DNS 해석기가 SRV 조회 실패

코드에 공개 DNS 지정(8.8.8.8)

배포 후 "Application error"

DB 접근 IP 허용목록에 집 IP만 있음

Atlas에 외부 접근 허용 → 재시작

배포하면 자꾸 `localhost`로 연결됨

`.env`가 깃에 안 올라감

**배포 호스트에 환경변수 직접 등록**

**🍯 나만의 꿀팁**

1.   **"내 PC에서 되는 것 ≠ 클라우드에서 되는 것"** — 포트·DB주소·API주소는 코드에 박지 말고 **환경변수**로 분리!

2.   비밀번호가 든 `.env`는 **절대 깃에 올리지 않기** (`.gitignore` 꼭 확인).

3.   비전공자일수록 AI에게 **한 번에 다 시키지 말고, 작은 단위로** 지시하고 검증하며 가기.

**🙋 도움이 필요한 부분**

*   지금은 1인용(공유 DB)인데, **로그인/회원 기능**을 붙여 사용자별로 데이터를 분리하는 방법을 더 배우고 싶습니다.

*   입문자 수준에서 **보안(비밀번호 관리, CORS 제한)** 을 깔끔히 적용하는 팁이 있다면 조언 부탁드려요!

**🚀 앞으로의 계획**

*   **로그인 기능 추가** → 여러 사용자가 안전하게 쓰는 서비스로 확장

*   마감 **알림**, 간단한 업무 **통계** 기능 추가

*   **모바일 화면 최적화**
